# TechSMP 部署說明(給管理主機的人)

這份是把 TechSMP 生電服部署到正式主機的步驟。所有設定(模組版本、模組設定、Carpet 規則、腳本)都在這個 repo 裡，
主機上只需要 Docker,外加我們的地圖。日常怎麼玩、怎麼調設定請看 [`說明.md`](說明.md)。

## 概要
- 核心:**Fabric 26.3**(原版伺服器 + Fabric 模組),用 Docker 映像 [`itzg/minecraft-server`](https://docker-minecraft-server.readthedocs.io/) 執行
- 伺服器模組(版本已釘死，第一次啟動自動從 Modrinth 下載):Carpet、Carpet TIS Addition、Servux、Syncmatica、Lithium、FerriteCore、Ledger、Chunky、VeinMiner
- 三個容器(都定義在 `docker-compose.yml`)

| 服務 | 容器名 | 預設 port | 用途 | 必要? |
|---|---|---|---|---|
| `mc` | `mc-techsmp` | 25566 | 生存服(正式世界) | 必要 |
| `backup` | `mc-techsmp-backup` | — | 每 3 小時備份世界到 `backups/`,保留 14 天 | 強烈建議 |
| `mirror` | `mc-techsmp-mirror` | 25567 | 創造模式鏡像服，每天從生存服複製世界，給大家測機器 | 選用 |

## 主機需求
| 項目 | 需求 |
|---|---|
| 系統 | Linux,裝好 Docker Engine 與 `docker compose`(v2)。**不需要另外裝 Java**(映像內建 Java 25) |
| 記憶體 | 生存服 heap 10 GB(容器上限 13 GB);鏡像服 6 GB(上限 8 GB)。全開約 21 GB,不夠可在 `.env` 調低或不開鏡像服 |
| 磁碟 | 世界大小 + 備份空間(zstd 壓縮，每 3 小時一份、留 14 天;建議預留世界大小的 10 倍以上) |
| 網路 | 玩家連入的 TCP port(預設 25566,鏡像服 25567)。RCON 不對外開放 |
| 對外連線 | 第一次啟動要能連 Modrinth、Mojang、Fabric 下載伺服器與模組 |

## 1. 取得 repo(唯讀 deploy key)
repo 是 private,建議用只能讀取這個 repo 的 deploy key:
```bash
ssh-keygen -t ed25519 -f ~/.ssh/catjj-mcs-deploy -N "" -C "catjj-mcs deploy"
cat ~/.ssh/catjj-mcs-deploy.pub      # 把這行公鑰傳給 Jay
```
Jay 到 repo → Settings → **Deploy keys** → Add deploy key 貼上(**不要勾** Allow write access)。之後:
```bash
GIT_SSH_COMMAND="ssh -i ~/.ssh/catjj-mcs-deploy -o IdentitiesOnly=yes" \
  git clone git@github.com:TsengJay0402/catjj-mcs.git
cd catjj-mcs
git config core.sshCommand "ssh -i ~/.ssh/catjj-mcs-deploy -o IdentitiesOnly=yes"   # 之後 git pull 免設定
```

## 2. 設定 `.env`
```bash
cd techsmp
cp .env.example .env && chmod 600 .env
```
編輯 `.env`:
- `RCON_PASSWORD`:填 `openssl rand -hex 24` 產生的字串
- `MC_UID` / `MC_GID`:填你帳號的 `id -u` / `id -g`(伺服器檔案會屬於這個帳號)
- `MC_PORT`:玩家連線用的 port;主機上沒有其他 Minecraft 服的話可以改成 25565(玩家就不用打 port)
- 記憶體不夠就調低 `MC_MEMORY` / `MC_MEM_LIMIT`

## 3. 放入地圖
1. **先停掉目前跑這張地圖的伺服器，並完整備份原始世界資料夾**(例如 `tar czf world-backup.tgz world/`)。
   如果地圖不是 26.3,第一次啟動會升級，**升級後無法回到舊版**。
2. 檢查地圖(只讀，不會改檔):
   ```bash
   python3 ../tools/level-info.py /path/to/地圖/world
   ```
   它會列出版本、資料夾結構和該怎麼搬。重點:
   - 版本 **比 26.3 新** → 停下來，先跟 Jay 確認(Minecraft 不能降版)
   - **Paper/Spigot 分開結構**(有 `world_nether/`、`world_the_end/`)→ 先把
     `world_nether/DIM-1` 搬到 `world/DIM-1`、`world_the_end/DIM1` 搬到 `world/DIM1`
3. 把世界放成 `techsmp/data/world`(資料夾名稱一定要是 `world`):
   ```bash
   mkdir -p data && cp -a /path/to/地圖/world data/world     # 或 mv
   sudo chown -R "$(id -u):$(id -g)" data                    # 擁有者要和 .env 的 MC_UID/MC_GID 一致
   ```

## 4. 第一次啟動
```bash
docker compose up -d mc backup
docker logs -f mc-techsmp          # Ctrl+C 離開，不會停服
```
會依序看到：下載 Fabric 和模組 → (舊版地圖)`World storage migration is required` 並倒數 30 秒(**正常**,已備份就讓它繼續)
→ `Done (...)! For help, type "help"` 代表完成。舊版地圖的區塊是「玩家走到時才轉換」,不會一次全部轉完。

確認:
```bash
docker exec mc-techsmp rcon-cli list                          # 有回應 = 伺服器正常
python3 ../tools/level-info.py data/world                     # 版本應變成 26.3,region 數量和原本相同
docker exec mc-techsmp rcon-cli "whitelist add <玩家ID>"       # 白名單已開啟，每個玩家都要加
docker exec mc-techsmp rcon-cli "op <玩家ID>"                  # 需要的人再給 OP
```
地圖已經有人玩過，就**不需要**跑 Chunky 預生成。

## 5. 鏡像服(選用)
```bash
./refresh-mirror.sh                # 第一次：複製世界並啟動鏡像服(約數十秒到數分鐘，視世界大小)
crontab -e                         # 加入下面這行(路徑改成實際位置),每天 05:00 自動同步
0 5 * * * /path/to/catjj-mcs/techsmp/refresh-mirror.sh >> /path/to/catjj-mcs/techsmp/logs/refresh-mirror.log 2>&1
```
鏡像服白名單要另外加:`docker exec mc-techsmp-mirror rcon-cli "whitelist add <玩家ID>"`。
同步時生存服會暫停自動存檔幾秒，腳本結束一定會恢復。

## 6. 日常維運
| 情況 | 指令(在 `techsmp/`) |
|---|---|
| Jay 說 repo 有更新 | `git pull && docker compose up -d`,只改了 `config/` 的話再 `docker compose restart mc mirror` |
| `carpet.conf` 有更新 | `./carpet-sync.sh push`(立即生效，免重啟) |
| 看 log | `docker logs -f mc-techsmp` |
| 停服 / 啟動 | `docker compose stop` / `docker compose up -d` |
| 看備份 | `ls -lh backups/` |

**不要直接改 `data/config/` 裡的檔案或用遊戲內指令改 Servux/VeinMiner 設定**:每次啟動都會被 repo 的 `config/` 蓋回去。
要改設定請跟 Jay 說，由 repo 修改。

### 還原備份
```bash
docker compose stop mc
mv data/world data/world.broken-$(date +%F)
tar -I zstd -xf backups/world-<時間>.tar.zst -C data ./world    # 只解出世界(備份檔裡有整個 /data)
docker compose up -d mc
```

## 7. 有問題時請提供
```bash
docker compose ps
docker logs --tail 200 mc-techsmp
python3 ../tools/level-info.py data/world
```
